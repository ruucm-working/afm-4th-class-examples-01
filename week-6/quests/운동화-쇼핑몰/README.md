# NALSSI · 날씨 운동화 쇼핑몰 (week-6 퀘스트)

CDN React 한 파일(`index.html`) + Express 한 파일(`server.js`) 로 만든 운동화 쇼핑몰.

- **배포**: https://nalssi-shoes.vercel.app
- **데모 데이터는 전부 DB(Supabase Postgres)에 있다** — 화면에는 상품 데이터가 한 줄도 없고 모두 `/api` 로 받아 온다
- **회원가입 · 로그인**: 이메일 + 비밀번호, JWT
- **결제**: 토스페이먼츠 결제위젯 → 서버 승인 → 재고 차감 → 마이페이지
- **이미지**: ImageKit CDN (`https://ik.imagekit.io/fbfjqppqm/nalssi/…`) · 화면에서 `?tr=w-600` 처럼 필요한 크기로 줄여 받는다
- **관리자 페이지** (`/#/admin`, 관리자 계정만): 상품 썸네일 · 설명 수정, 회원 목록, 모든 회원의 주문 내역 → [아래](#관리자-페이지)

## 실행

```bash
npm install
node server.js      # http://localhost:6070
node server.js create-admin <이메일> [비밀번호] [이름]   # 관리자 계정 만들기
```

`.env` 가 필요하다 (`.env.example` 참고). **`.env` 는 깃 · Vercel 업로드 모두에서 빠진다.**

| 키 | 쓰임 |
| --- | --- |
| `DATABASE_URL` | Supabase Postgres 연결 문자열 (Transaction pooler, 6543) |
| `TOSS_CLIENT_KEY` | 결제위젯 클라이언트 키. 공개되어도 되는 값 → `/api/config` 로 브라우저에 내려준다 |
| `TOSS_SECRET_KEY` | 결제 승인용 시크릿 키. **브라우저에 절대 내려보내지 않는다** |
| `JWT_SECRET` | 토큰 서명 키 |
| `IMAGEKIT_PUBLIC_KEY` · `IMAGEKIT_PRIVATE_KEY` | 관리자 페이지 썸네일 업로드. 서버가 비공개 키로 1회용 서명만 만들어 주고 파일은 브라우저가 ImageKit 에 직접 올린다. **비공개 키는 브라우저에 내려보내지 않는다** |
| `IMAGEKIT_URL_ENDPOINT` | 데모 이미지를 한꺼번에 다시 올릴 때만 쓴다 (서버 런타임은 안 씀) |

Vercel 에는 `DATABASE_URL` · `TOSS_CLIENT_KEY` · `TOSS_SECRET_KEY` · `JWT_SECRET` · `IMAGEKIT_PUBLIC_KEY` · `IMAGEKIT_PRIVATE_KEY` 를 Production 환경변수로 넣었다 (ImageKit 두 개는 2026-10-13 관리자 페이지와 함께 추가).

## DB 에 들어간 데모 데이터

첫 `/api` 요청 때 테이블을 만들고(lazy init), 상품이 비어 있으면 `server.js` 의 `DEMO` 를 한 번 넣는다.
그 뒤로는 **DB 가 원본**이다. DB 에서 가격을 바꾸면 화면과 결제 금액이 같이 바뀐다.

| 테이블 | 행 | 내용 |
| --- | --- | --- |
| `nalssi_categories` | 4 | 러닝 · 스니커즈 · 아웃도어 · 하이탑 |
| `nalssi_products` | 12 | 모델 · 가격 · 정가 · 배지 · 소재 · 무게 · 특징 |
| `nalssi_variants` | 24 | 모델별 컬러 2개 + ImageKit 이미지 주소 |
| `nalssi_stock` | 360 | 컬러 × 사이즈(220–290mm) 재고. 결제되면 줄어든다 |
| `nalssi_reviews` | 31 | 별점 · 사이즈 · 착용감 · 내용 |
| `nalssi_stories` | 6 | 홈 히어로 · 룩북 3 · 스토리 · 다음 드롭 |
| `nalssi_users` · `nalssi_orders` | — | 회원(`role` = `customer` · `admin`) · 주문 |

평점 · 리뷰 수 · 남은 재고는 따로 저장하지 않고 매번 리뷰 · 재고 테이블에서 센다.
데모 데이터를 처음 상태로 되돌리려면 `nalssi_` 테이블을 지우고 서버에 아무 `/api` 요청을 보내면 다시 들어간다.

## API

| 메서드 | 경로 | 요청 | 응답 |
| --- | --- | --- | --- |
| GET | `/api/config` | — | `{ tossClientKey, shippingFee, freeShippingOver, maxQtyPerLine, paymentEnabled }` |
| GET | `/api/categories` | — | 카테고리 + 상품 수 |
| GET | `/api/stories` | — | 히어로 · 룩북 · 스토리 · 드롭 |
| GET | `/api/products` | `?category= &sort=recommended\|new\|rating\|price-asc\|price-desc &q= &limit=` | 상품 목록 (컬러 · 평점 · 남은 재고) |
| GET | `/api/products/:id` | — | 상세 + 컬러별 사이즈 재고 + 리뷰 + 착용감 요약 |
| POST | `/api/auth/signup` | `{ email, password, name? }` | `{ token, user }` · 비밀번호 8자 이상 |
| POST | `/api/auth/login` | `{ email, password }` | `{ token, user }` |
| GET | `/api/auth/me` | 🔒 | `{ user }` — 새로고침해도 로그인 유지 |
| POST | `/api/orders` | 🔒 `{ items: [{ variantId, size, qty }] }` | 주문서 + `customerKey`. 금액 · 재고는 **서버가 DB 로 계산** |
| GET | `/api/orders` | 🔒 `?status=PAID\|FAILED\|all` | 주문 내역(최신순) + `summary` |
| GET | `/api/orders/:orderId` | 🔒 | 주문 상세 (본인 것만 · 입금 대기면 토스에 입금 여부 확인) |
| GET | `/api/payments/success` | 토스 리다이렉트 | 승인 + 재고 차감 후 `#/orders/:id?paid=1` |
| GET | `/api/payments/fail` | 토스 리다이렉트 | 실패 기록 후 `#/cart?failed=1` |
| POST | `/api/payments/confirm` | 🔒 `{ paymentKey, orderId, amount }` | 브라우저에서 직접 승인할 때 |
| POST | `/api/payments/webhook` | 토스 웹훅 | 가상계좌 입금 · 취소 반영 (승인 때 받은 `secret` 과 같을 때만) |
| GET | `/api/admin/upload-auth` | 🛡 | ImageKit 1회용 업로드 서명 `{ uploadUrl, folder, publicKey, token, expire, signature }` (10분) |
| PATCH | `/api/admin/products/:id` | 🛡 `{ tagline?, description?, images?: [{ variantId, image }] }` | 수정된 상품. 보낸 칸만 바꾼다 (한 줄 소개 ≤ 60자 · 상세 설명 ≤ 1000자 · 이미지는 `https://` 주소) |
| GET | `/api/admin/users` | 🛡 `?q=` | 회원 목록(최근 가입순) + 회원별 결제 건수 · 금액 · 최근 주문 + `summary` |
| GET | `/api/admin/orders` | 🛡 `?status=PAID\|WAITING_FOR_DEPOSIT\|FAILED\|READY\|ALL &userId= &q=` | 모든 회원의 주문(회원 이름 · 이메일 포함) + 상태별 `summary` |

🔒 = `Authorization: Bearer <token>`. 🛡 = 🔒 + 관리자(`role = 'admin'`)만 — 로그인 안 함 401 · 일반 회원 403. 응답은 전부 `{ success, data, message? }` 모양.

## 결제가 도는 순서

1. `/checkout` 이 `POST /api/orders` 로 **주문서를 먼저 만든다** → 서버가 DB 가격 · 재고로 금액을 계산
2. 그 금액으로 토스 결제위젯을 그린다 (카드번호 · 계좌는 토스만 본다)
3. 결제가 끝나면 토스가 `/api/payments/success` 로 되돌려 보낸다
4. 서버가 **한 트랜잭션에서** 주문을 `PAYING` 으로 잠그고 재고를 뺀다 → 한 줄이라도 모자라면 아무것도 안 빠진다
5. 시크릿 키로 토스 최종 승인 → 성공이면 `PAID`, 실패면 재고를 돌려놓고 `FAILED`
6. 무통장입금(가상계좌)이면 `WAITING_FOR_DEPOSIT` 으로 두고 재고를 계속 잡아 둔다 → 웹훅이나 주문 조회 때 입금이 확인되면 `PAID`

## 관리자 페이지

`/#/admin` — 관리자 계정으로 로그인하면 헤더에 「관리자」 버튼이 생긴다 (모바일은 메뉴 안 · 마이페이지에도 버튼).

| 탭 | 할 수 있는 것 |
| --- | --- |
| 상품 | 12개 상품 목록 → 상품마다 **썸네일**(컬러별 사진 · 첫 컬러가 상품 목록의 대표 썸네일)과 **한 줄 소개 · 상세 설명** 수정. 사진은 파일로 올리거나(5MB 이하) 주소를 붙여 넣는다. 옆에 상품 카드 미리보기. 가격 · 재고는 결제 금액과 묶여 있어 여기서 바꾸지 않는다 |
| 회원 | 최근 가입순 목록 · 이름/이메일 검색 · 회원별 결제 완료 건수 · 결제 금액 · 최근 주문 → 「주문 보기」로 그 회원 주문만 |
| 주문 | 모든 회원의 주문 · 매출 · 상태별 건수(결제 완료 · 입금 대기 · 결제 실패 · 결제 대기) · 주문번호/상품/회원 검색 → 줄을 누르면 상세(상품 · 금액 · 결제 수단 · paymentKey · 영수증 · 실패 사유) |

### 관리자 계정 만들기

회원가입으로는 관리자가 될 수 없다 (`role` 은 항상 `customer` 로 들어간다). 서버 `.env`(DB 주소)를 가진 사람만 터미널에서 만든다.

```bash
node server.js create-admin admin@example.com '비밀번호' '이름'   # 없으면 만들고, 있으면 관리자로 올리고 비밀번호를 바꾼다
node server.js create-admin someone@example.com                   # 있는 회원을 관리자로만 올린다 (비밀번호 그대로)
```

없는 이메일에 비밀번호를 비우면 무작위 비밀번호를 만들어 한 번만 보여 준다.
관리자에서 빼려면 DB 에서 `UPDATE nalssi_users SET role = 'customer' WHERE email = '…'`.
실제로 쓰는 관리자 계정의 비밀번호는 저장소에 적지 않는다 (DB 에도 bcrypt 해시만 있다).

### 이렇게 막았다

- `/api/admin` 아래 **모든** 주소에 `requireAuth` → `requireAdmin` 을 한 번에 건다 → 관리자 API 를 새로 만들 때 깜빡해도 열리지 않는다
- 토큰에는 회원 번호만 있고, 관리자인지는 **매 요청 DB 의 `role`** 로 판단 → 토큰을 위조할 수 없고, DB 에서 권한을 빼면 이미 로그인한 관리자도 바로 막힌다
- 화면에서 관리자 메뉴를 숨기는 건 안내용일 뿐이고 진짜 문지기는 서버다
- 회원 목록에 비밀번호 해시 · 토스 `customerKey` 를, 주문 목록에 가상계좌 웹훅 비밀값을 내려보내지 않는다
- 썸네일 업로드: 서버가 ImageKit 비공개 키로 **1회용 서명**(10분)만 만들어 주고 파일은 브라우저가 ImageKit 에 직접 올린다 → 비공개 키는 브라우저로 나가지 않고, 큰 사진이 서버리스 요청 한도(4.5MB)에 걸리지 않는다
- 이미지 주소는 `https://` 만 받는다 (javascript: · http: · 상대 경로 거절). 글자와 사진을 한 트랜잭션으로 바꿔서, 다른 상품의 컬러를 섞어 보내면 **아무것도 안 바뀐다**

**막아 둔 것** (API 로 직접 찔러서 확인 · 로컬과 배포 둘 다)

- 클라이언트가 `price: 100` 을 보내도 무시하고 DB 가격으로 계산 · 같은 컬러/사이즈 두 줄은 한 줄로 합침
- 승인 금액을 100원으로 조작 → `AMOUNT_MISMATCH` 로 차단 (토스까지 가지도 않음)
- 가짜 `paymentKey` 로 승인 → 토스가 거절 → **잡았던 재고가 그대로 돌아옴**
- 품절 사이즈 · 재고 초과 · 없는 사이즈 · 없는 상품 · 한 줄 10개 초과 → 409 · 400
- 남의 주문 조회 → 404 · 위조 토큰 → 401 · 잘못된 JSON → 400 · 비밀값이 틀린 웹훅 → 400
- `/server.js` · `/.env` · `/package.json` 으로 접근해도 파일 내용이 나가지 않음

**확인 못 한 것**

- **무통장입금(가상계좌)** — 토스 문서용 테스트 키(`test_gck_docs_…`)의 결제위젯에는 결제수단이 퀵계좌이체 · 카드 · 토스페이 · 페이코 · 카카오페이 · 네이버페이 6개뿐이라 고를 수 없었다. 서버의 입금 대기 · 웹훅 · 입금 확인 코드는 넣어 두었지만 실제 결제로 돌려 보지 못했다. 내 상점 키로 바꾸고 개발자센터에서 가상계좌를 켜면 테스트할 수 있다(테스트 입금은 개발자센터 「테스트 결제내역 → 입금처리」, 웹훅 주소는 `https://nalssi-shoes.vercel.app/api/payments/webhook`).
- **카드 · 토스페이 등** — 카드사 앱 · 토스 앱 본인인증으로 넘어가 자동화로 끝까지 갈 수 없다. 서버가 부르는 승인 API(`/v1/payments/confirm`)는 결제수단과 상관없이 같다.

**API 로 직접 찔러서 확인** (로컬 57개 · 배포 55개 항목 모두 통과 — 배포에선 회원가입 2개 항목을 빼고 로컬에서 만든 일반 회원을 다시 썼다)

- 관리자 API 5개 주소 모두 토큰 없음 · 위조 토큰 → 401, 일반 회원 → 403
- 회원가입 body 에 `role: 'admin'` 을 끼워 넣어도 `customer` 로 가입됨
- 회원 목록에 비밀번호 해시 · `customerKey` 없음, 주문 목록에 웹훅 비밀값 없음, 업로드 서명 응답에 비공개 키 없음 (서명은 매번 새 token)
- 검색어 `%` 는 와일드카드가 아니라 글자로 찾음 · 이상한 `status` · `userId` 는 무시
- 상품 수정: 빈 body · 빈 한 줄 소개 · 61자 · 1001자 · `javascript:` / `http:` / 상대 경로 이미지 → 400, 다른 상품 컬러 섞기 → 400 + 함께 보낸 문구도 안 바뀜(롤백), 없는 상품 → 404
- 정상 수정 → 공개 상품 API 에 바로 반영 → 원래 값으로 되돌림

검증하며 바꾼 상품 문구 · 사진은 끝나고 원래대로 돌려놓았고, ImageKit `/nalssi/uploads/` 에 올린 테스트 사진 3장은 지웠다.
차단 확인용 일반 회원 `e2e-customer+…@nalssi.dev` 한 명이 회원 목록에 남아 있다.
