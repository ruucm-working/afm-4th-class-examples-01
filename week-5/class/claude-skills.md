# 클로드 스킬 (Claude Skills)

> 한 줄 요약: **스킬 = "이런 일은 이렇게 해" 를 적어 둔 폴더.** 클로드가 필요할 때 꺼내 읽고 그대로 따라 한다.

---

## 1. 스킬이란?

스킬은 특정 작업을 잘 해내기 위한 **지침서 + 도구 모음**을 하나의 폴더로 묶은 것이다.

- 매번 프롬프트에 "PDF 는 이렇게 만들고, 한글 폰트는 이걸 쓰고…" 라고 설명할 필요가 없다
- 한 번 잘 적어 두면 **누가, 언제 요청해도 같은 품질**로 결과가 나온다
- 설명(`SKILL.md`)뿐 아니라 **스크립트, 템플릿, 참고 자료**까지 같이 넣을 수 있다

비유하면, 신입 직원에게 건네는 **업무 매뉴얼 바인더**다. 평소엔 책꽂이에 꽂혀 있다가, 해당 업무가 들어오면 펼쳐 본다.

---

## 2. 폴더 구조

```
.claude/skills/
└── yt-dlp/                 ← 스킬 하나 = 폴더 하나
    ├── SKILL.md            ← (필수) 지침서
    ├── scripts/            ← (선택) 실행할 스크립트
    │   └── fetch.sh
    └── references/         ← (선택) 필요할 때만 읽는 참고 문서
        └── options.md
```

필수 파일은 `SKILL.md` 하나뿐이다.

---

## 3. SKILL.md 작성법

맨 위에 **frontmatter**(`---` 로 감싼 부분)를 두고, 그 아래에 본문을 쓴다.

```markdown
---
name: yt-dlp
description: 유튜브 주소로 자막·음성·메타데이터를 내려받을 때 사용. "이 유튜브 자막 받아줘", "영상 내용 정리해줘" 같은 요청에 사용.
---

# yt-dlp — 영상·자막·메타데이터 내려받기

## 1. 작업 절차
1. 메타데이터 먼저 받는다
2. 자막 시도 — ko → en → 자동 자막
3. 자막이 없으면 음성(mp3)만 받고 whisper 스킬로 넘긴다

## 2. 실행
bash .claude/skills/yt-dlp/scripts/fetch.sh "<URL>" <출력폴더>
```

| 항목 | 역할 | 팁 |
|---|---|---|
| `name` | 스킬 이름 (폴더명과 동일하게) | 소문자-하이픈 |
| `description` | **언제 이 스킬을 쓸지** 판단 기준 | 가장 중요! 실제 요청 문장 예시를 넣는다 |
| 본문 | 작업 절차, 규칙, 주의점, 예시 | 짧고 명령형으로 |

### description 이 왜 가장 중요한가?

클로드는 평소에 스킬의 **name 과 description 만** 알고 있다. 사용자의 요청이 description 과 맞아떨어질 때 비로소 본문을 읽는다.
→ description 이 모호하면 스킬이 **아예 호출되지 않는다.**

```yaml
# ❌ 나쁜 예
description: PDF 관련 스킬

# ✅ 좋은 예
description: PDF 파일을 만들거나 읽거나 합치거나 나눌 때 사용. "PDF 로 만들어줘", "이 PDF 텍스트 뽑아줘", ".pdf" 가 언급되면 사용.
```

## 4. 동작 원리 — 점진적 로딩 (Progressive Disclosure)

스킬은 컨텍스트(클로드의 작업 기억)를 아끼기 위해 **필요한 만큼만 단계적으로** 읽힌다.

| 단계 | 언제 | 읽는 내용 | 크기 |
|---|---|---|---|
| ① 목록 | 항상 | 모든 스킬의 `name` + `description` | 아주 작음 |
| ② 본문 | 요청이 description 과 맞을 때 | `SKILL.md` 전체 | 중간 |
| ③ 부속 파일 | 본문이 "이 파일을 봐라" 할 때 | `references/`, `scripts/` 등 | 필요한 것만 |

그래서 스킬을 수십 개 설치해도 평소 부담이 거의 없다.

## 5. 스킬을 두는 위치

| 위치 | 범위 | 용도 |
|---|---|---|
| `~/.claude/skills/<이름>/` | 내 컴퓨터의 **모든 프로젝트** | 개인용 스킬 |
| `<프로젝트>/.claude/skills/<이름>/` | **이 프로젝트만** | 팀과 git 으로 공유 |
| 플러그인 | 플러그인을 설치한 곳 | 배포·재사용 |

> Claude Code 뿐 아니라 claude.ai 웹/앱, Claude API 에서도 스킬을 사용할 수 있다.

---

## 6. 스킬 호출 방법

1. **자동 호출** — 그냥 평소처럼 말하면 된다
   `"이 유튜브 자막 받아줘"` → 클로드가 `yt-dlp` 스킬을 알아서 꺼내 씀
2. **직접 호출** — 슬래시 명령으로 이름을 부른다
   `/yt-dlp https://youtu.be/XXXX`

## 7. 비슷한 기능과 비교

| 기능 | 무엇인가 | 언제 읽히나 | 예시 |
|---|---|---|---|
| **CLAUDE.md** | 프로젝트 공통 규칙 | **항상** | "작업 파일은 week- 폴더 아래에" |
| **스킬** | 특정 작업의 매뉴얼 | **필요할 때만** | "PDF 만들 땐 이 폰트·이 스크립트" |
| **서브에이전트** | 일을 따로 맡기는 조수 | 위임할 때 | "코드베이스 전체 검색해 와" |
| **MCP** | 외부 서비스 연결 통로 | 도구 호출 시 | 브라우저 조작, DB 조회 |
| **훅(Hook)** | 특정 시점에 자동 실행 | 이벤트 발생 시 | "파일 저장 후 항상 포맷터 실행" |

**구분 요령**
- 항상 지켜야 하는 규칙 → `CLAUDE.md`
- 가끔 하는 특정 작업의 노하우 → **스킬**
- 외부 시스템에 접근해야 함 → MCP
- "매번 반드시" 자동으로 실행돼야 함 → 훅

## 9. 나만의 스킬 만들기 — 5단계

1. **반복되는 작업을 찾는다** — "이거 매번 똑같이 설명하네?" 싶은 것
2. **폴더를 만든다** — `.claude/skills/my-skill/`
3. **SKILL.md 를 쓴다** — `name`, `description`(요청 예시 포함), 작업 절차
4. **스크립트·참고자료를 넣는다** — 반복 실행하는 명령은 `scripts/` 로
5. **실제로 요청해 보고 고친다** — 호출이 안 되면 description 을, 결과가 이상하면 본문을 수정

### 좋은 스킬 체크리스트

- [ ] description 에 **실제 사용자가 할 법한 문장**이 들어 있다
- [ ] 본문이 **짧고 명령형**이다 (설명문보다 절차)
- [ ] 자주 틀리는 부분(**함정·주의점**)이 적혀 있다
- [ ] 긴 참고 자료는 `references/` 로 분리했다
- [ ] 결과물 형태(파일명, 위치, 형식)가 명확하다
- [ ] API 키 같은 비밀값은 스킬 안에 **직접 쓰지 않고** `.env` 에서 읽는다
